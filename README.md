# Spark-Scala Reconciliation Framework

## Overview

This is a generic, configuration-driven reconciliation framework built using Apache Spark and Scala. It is designed to be a robust, enterprise-ready solution for data reconciliation between various sources and targets. The framework is entirely driven by a single Oracle configuration table, eliminating the need for external configuration files like JSON or YAML.

## Key Features

- **Configuration-Driven**: All reconciliation jobs, including source/target details, mappings, and logic, are defined as rows in a single Oracle table.
- **Two Reconciliation Modes**:
    1. **Source-to-Target**: Compares a source dataset against a defined target dataset.
    2. **Source-to-SQL**: Compares a source dataset against a derived dataset generated by executing a complex SQL query on the source environment.
- **Extensive Reconciliation Types**: Supports six types of reconciliation checks:
    1. **Column-level Comparison**: Compares values of mapped columns between source and target.
    2. **Business Rule Validation**: Applies complex SQL logic to the source and compares the result with the original dataset.
    3. **Count-level Reconciliation**: Compares record counts.
    4. **Extra/Missing Record Check**: Identifies records present in one dataset but not the other, based on primary keys.
    5. **Threshold-based Validation**: Validates numeric fields against absolute or percentage deviation thresholds.
    6. **Schema Drift Detection**: Compares column names, data types, order, and count.
- **Broad Source/Target Support**:
    - **Sources**: Local files (CSV, Excel, Text, DAT, Parquet, ORC), Hive tables, and JDBC sources.
    - **Targets**: Hive tables, Parquet, and ORC files.
- **Auditing and Reporting**:
    - **Audit Summary**: Writes a summary of each job's execution to a Hive table.
    - **Mismatch Details**: Logs detailed mismatch records to a dedicated Hive table.
    - **HTML Email Reports**: Sends detailed HTML reports to configured recipients.
- **Modular and Extensible**: Built with a clean, modular architecture that is easy to extend.

## Configuration Table Schema

The entire framework is controlled by the `RECON_CONFIG` table in an Oracle database.

```sql
CREATE TABLE RECON_CONFIG (
    JOB_ID NUMBER PRIMARY KEY,
    JOB_NAME VARCHAR2(255) UNIQUE NOT NULL,
    RECON_MODE VARCHAR2(20) NOT NULL, -- 'SOURCE_TO_TARGET' or 'SOURCE_TO_SQL'

    -- Source Details
    SOURCE_TYPE VARCHAR2(20) NOT NULL, -- 'CSV', 'EXCEL', 'TEXT', 'DAT', 'PARQUET', 'ORC', 'HIVE', 'JDBC'
    SOURCE_PATH VARCHAR2(1000),
    SOURCE_JDBC_URL VARCHAR2(1000),
    SOURCE_JDBC_USER VARCHAR2(255),
    SOURCE_JDBC_PASSWORD VARCHAR2(255),
    SOURCE_JDBC_DRIVER VARCHAR2(255),
    SOURCE_HIVE_TABLE VARCHAR2(255),
    SOURCE_PRIMARY_KEYS VARCHAR2(1000),
    SOURCE_DELIMITER VARCHAR2(5),

    -- Target Details (for SOURCE_TO_TARGET mode)
    TARGET_TYPE VARCHAR2(20), -- 'HIVE', 'PARQUET', 'ORC'
    TARGET_PATH VARCHAR2(1000),
    TARGET_HIVE_TABLE VARCHAR2(255),
    TARGET_PRIMARY_KEYS VARCHAR2(1000),

    -- SQL Details (for SOURCE_TO_SQL mode)
    RECON_SQL CLOB,

    -- Reconciliation Types (Flags: 'Y'/'N')
    DO_COLUMN_COMPARISON CHAR(1) DEFAULT 'N',
    DO_BUSINESS_RULE_VALIDATION CHAR(1) DEFAULT 'N',
    DO_COUNT_RECONCILIATION CHAR(1) DEFAULT 'N',
    DO_EXTRA_MISSING_CHECK CHAR(1) DEFAULT 'N',
    DO_THRESHOLD_VALIDATION CHAR(1) DEFAULT 'N',
    DO_SCHEMA_DRIFT_DETECTION CHAR(1) DEFAULT 'N',

    -- Mappings and Thresholds
    COLUMN_MAPPINGS CLOB, -- 'source_col1:target_col1,source_col2:target_col2'
    THRESHOLD_SETTINGS CLOB, -- 'col1:absolute:100,col2:percentage:5.5'

    -- Email Settings
    EMAIL_RECIPIENTS VARCHAR2(1000),
    EMAIL_SUBJECT VARCHAR2(255),

    -- Auditing
    AUDIT_HIVE_TABLE VARCHAR2(255),
    MISMATCH_HIVE_TABLE VARCHAR2(255),

    -- Job Control
    IS_ACTIVE CHAR(1) DEFAULT 'Y'
);
```

## How to Run a Reconciliation Job

1. **Configure the Job**: Add a new row to the `RECON_CONFIG` table for your reconciliation job.
2. **Build the Project**:
   ```bash
   mvn clean package
   ```
3. **Submit the Spark Job**:
   ```bash
   spark-submit \
     --class com.reconciliation.framework.Main \
     --master <your_spark_master> \
     target/spark-reconciliation-framework-1.0.0-jar-with-dependencies.jar \
     <job_name>
   ```
   Replace `<your_spark_master>` with your Spark master URL and `<job_name>` with the `JOB_NAME` from the `RECON_CONFIG` table.

## Supported Data Types and Reconciliation Checks

### Data Sources and Targets

| Type    | Source | Target |
|---------|--------|--------|
| CSV     | Yes    | No     |
| Excel   | Yes    | No     |
| Text    | Yes    | No     |
| DAT     | Yes    | No     |
| Parquet | Yes    | Yes    |
| ORC     | Yes    | Yes    |
| Hive    | Yes    | Yes    |
| JDBC    | Yes    | No     |

### Reconciliation Types Explained

- **Column-level Comparison**: Compares data for each column specified in `COLUMN_MAPPINGS`.
- **Business Rule Validation**: Executes the SQL in `RECON_SQL` and compares the result against the source data.
- **Count-level Reconciliation**: Compares the row counts of the source and target.
- **Extra/Missing Record Check**: Uses the `SOURCE_PRIMARY_KEYS` and `TARGET_PRIMARY_KEYS` to find records that exist in one dataset but not the other.
- **Threshold-based Validation**: For numeric columns, validates that the difference between source and target values is within the configured threshold (absolute or percentage).
- **Schema Drift Detection**: Checks for differences in column names, data types, and column order.

## Auditing and Reporting

- **Audit Summary**: A high-level summary of each job is written to the `AUDIT_HIVE_TABLE`.
- **Mismatch Details**: Detailed records of any mismatches are written to the `MISMATCH_HIVE_TABLE`, with a `MISMATCH_TYPE` column to identify the type of discrepancy.
- **HTML Email Reports**: An HTML email report is sent to the addresses in `EMAIL_RECIPIENTS`, with a summary of the reconciliation and details of any mismatches.
